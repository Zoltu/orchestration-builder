# Step 02 — CLI entry point + executor public API

## Goal

Create a CLI entry point (`source/main.ts`) so the executor can be invoked end-to-end from the command line, and a public API barrel (`source/executor/index.ts`) so external callers import a single surface. After this step the executor is runnable against a real LLM endpoint (the run itself is operator work; step 03 adds an in-memory integration test).

## Context

Read [`00-foundation-completed.md`](00-foundation-completed.md) and `source/executor/executor.ts` (`runExecutor` assembles `ExecutorDependencies` and calls `runRole`). Dependencies that are leaf factories: `createLlmCaller` (`source/executor/llm.ts`), `createRunDirectory`/`createCopyWorkspace`/`createAppendLog`/`createWriteMeta`/`createSnapshotWorkspace` (`source/executor/persistence.ts`), `createGuildLoader` (`source/executor/loader.ts`), `createHumanBackend` (`source/executor/human-backend.ts`), `createToolHandlers` (`source/executor/tools.ts`), `createBuiltInToolHandlers` (`source/executor/builtin-tools.ts`). Per AGENTS.md, `main` is the **only** place that assembles real dependencies.

## Deliverables

1. `source/executor/index.ts` — public barrel exporting only what external callers need: `runExecutor`, the leaf factories above, `ExecutorDependencies`, `RunOptions`, `RunMeta`, `ResultCard`, and the `HumanBackend` type. Do not re-export internal helpers.
2. `source/main.ts` — CLI entry point. It is the integration shell and is **not** unit-tested (per the "Not testable" testing policy). It:
   - Parses CLI args: `--guild <path>`, `--workspace <path>`, `--task <text>`, optional `--run-id <id>`, optional `--human-backend <stub|foundry|web>` (only `stub` exists today; `foundry`/`web` are future).
   - Reads the model API key from an environment variable (e.g. `ORCHESTRATOR_API_KEY`) when present; never reads secrets into the Guild.
   - Generates a run id when `--run-id` is omitted (e.g. timestamp-based).
   - Assembles real leaf factories and calls `runExecutor(dependencies, options)`.
   - Prints the final status and exits with an appropriate code (`0` for success, non-zero for error/needs_clarification).
3. `source/main/args.ts` (or `source/main-args.ts`) — a **pure** arg-parsing helper that takes a `string[]` and returns a typed options object or a clear parse error. This is the testable surface; `main.ts` is a thin caller of it. Export it so it can be unit-tested.
4. `source/main-args.test.ts` (or `source/main/args.test.ts`) — in-memory tests: valid full args; valid minimal args (run id auto-generated by `main`, so the parser marks it optional); missing required args produce a clear error; unknown flags are rejected or ignored per a documented rule.
5. `package.json` — add a `start` script (e.g. `"start": "bun source/main.ts"`) so the operator can run `bun run start -- --guild guild ...`.
6. `README.md` — add a "Running the executor" section with the exact `bun source/main.ts ...` invocation and the environment variable for the API key.

## Module boundaries

- `main.ts` is the only file that reads `process.argv` and `Bun.env`. It is not tested.
- `args.ts` is a pure helper, imported by `main.ts`, and is unit-tested.
- `index.ts` is a barrel only — no logic.
- No new dependencies. Use Bun built-ins for HTTP/process/args only.

## Acceptance criteria

- [ ] `bun run typecheck` passes.
- [ ] `bun test source/` passes, including `main-args.test.ts`.
- [ ] `bun source/main.ts --help` (or an invalid invocation) prints a clear usage message and exits non-zero without crashing.
- [ ] The barrel `source/executor/index.ts` compiles and `main.ts` imports exclusively from it (plus the pure arg helper).
- [ ] `README.md` documents the CLI invocation and the API-key environment variable.

## End-of-step evaluation

Confirm `main.ts` is thin: all logic is in `args.ts` or in already-tested orchestration. Check that no leaf factory is assembled anywhere except `main.ts` (grep for `create*` calls). Ensure `index.ts` exports exactly the intended public surface.

## Estimated effort

Small to medium — mostly wiring; the arg parser is the only new testable logic.

## Operator handoff

Optional smoke check (not required to close the step): with a real OpenAI-compatible endpoint reachable, run `bun source/main.ts --guild guild --workspace benchmarks/hello_001 --task "Write a file called output.txt containing the text hello world" --run-id smoke-try` and observe `data/runs/smoke-try/meta.json`. Do not block the step on this; step 03 covers in-environment verification.
